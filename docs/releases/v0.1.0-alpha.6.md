# BoundedCode v0.1.0-alpha.6

**A crash test that records what it saw, and a reproducible licenses archive.**

No product code has changed since [v0.1.0-alpha.5](v0.1.0-alpha.5.md): the
binaries differ only in their version string. This alpha publishes the
crash-recovery test's own record of a kill and resume, makes every release
file reproducible regardless of the builder's umask, and fixes two smoke
tests that passed only on a warm module cache.

The local default, Qwen3.6-35B-A3B on Linux with an NVIDIA GPU, is still the
only validated configuration.

## Verification

- **A recorded crash and resume.** `TestSIGKILLResume` kills a runner
  process with SIGKILL in the middle of an agent turn, checks that a second
  runner is refused while the lease is fresh, and that a third takes over
  once it is stale and finishes the task. It now writes down every value it
  checks, in order, and compares the sequence with
  [`internal/orchestrator/testdata/crash-replay.json`](../../internal/orchestrator/testdata/crash-replay.json).
  - **Any difference fails the test,** so a passing CI run proves the file is
    what a real kill and resume produced at that commit.
  - **Normalised:** task ids and wall-clock times are replaced by
    placeholders, so the file is identical on every run.
  - **Rewriting it** on purpose: `go test ./internal/orchestrator -run
    '^TestSIGKILLResume$' -update-replay`.

## Releases you can verify

- **Reproducible licenses archive.** `make dist` now fixes the archive's
  permission bits instead of taking them from the builder's umask, so a
  local rebuild matches the CI release byte for byte. With alpha.5 this held
  only under `umask 022`.
- Attestation and rebuild steps are unchanged:
  [Verifying a release](../development/release.md#verifying-a-release).

## Tests and CI

- **Smoke tests without a warm module cache.** Two first-task smoke tests
  passed only on machines whose Go module cache was already populated. The
  offline-build test module now ships a `go.sum` and lists its indirect
  requirements, and the workflow downloads the Temporal Go SDK before the
  task that builds it.

## Documentation

- **[Engineering case study](../public-launch/engineering-case-study.md):**
  problem, architecture, every evaluation with its numbers, the documented
  false verification passes, limitations and lessons.
- **Adoption and feedback:** what counts as external adoption, a first-run
  issue form, templates for reproduction records and outside feedback, and a
  triage process.
- **Corrections** to two stale statements in the getting-started path.

**Benchmarks for this release.** No product code has changed since alpha.5,
whose benchmark section still applies; the task and infrastructure
benchmarks were not re-run.

## Known limitations

1. **Serena's pinned Python environment** (`configs/serena/uv.lock`) pins
   urllib3 2.7.0 and Werkzeug 3.1.7, which have open advisories
   (GHSA-vxq7-64xx-v4gw, GHSA-8988-9cw3-xx77, GHSA-gh4c-6fx4-qh6g and
   GHSA-g6x2-hccm-hh4m; fixed in urllib3 2.8.0 and Werkzeug 3.1.9). Serena
   v1.7.0 itself requires exactly these versions (`urllib3==2.7.0`,
   `werkzeug==3.1.7`), so the lock cannot move without overriding Serena's
   own requirements. That needs the compatibility review the pin policy
   requires for Serena (ADR-0008).
2. **Earlier limitations.** The limitations of
   [v0.1.0-alpha.5](v0.1.0-alpha.5.md#known-limitations) still apply.

## Assets

- **Binaries:** `boundedcode-linux-amd64`, `boundedcode-linux-arm64`,
  `boundedcode-darwin-amd64`, `boundedcode-darwin-arm64`,
  `boundedcode-windows-amd64.exe` and `boundedcode-windows-arm64.exe`.
  They are static (CGO disabled).
- **`SHA256SUMS`:** checksums, verified by the installers.
- **`SBOM-<os>-<arch>.spdx.json`:** an SPDX 2.3 software bill of materials
  for each binary.
- **`boundedcode-v0.1.0-alpha.6-licenses.tar.gz`:** `LICENSE`, `NOTICE`,
  `THIRD_PARTY_NOTICES.md`, and the license texts of every Go module
  compiled into the binaries (`LICENSES/go`) and of the upstream
  components (`LICENSES/upstream`).
